# Prepare Hockenworks Twitter/X and LinkedIn drafts

Start after the exact public article and its homepage featured image pass the
[hockenworks-site live check](publishing-workflow.md).
Use the public article URL, never its unlisted preview or the homepage.

## Copy and identity

Brian supplies the one- or two-sentence announcement. Ask for it early during the
publication workflow if it is missing. Use that text verbatim, followed by the
article URL, for both platforms unless he supplies separate versions. Do not
invent a teaser, rewrite his voice, add hashtags/mentions, expand to a thread,
or create a native LinkedIn article. If a platform rejects the supplied length,
ask for a shorter version instead of silently truncating it.

Profiles are sourced from `https://hockenworks.com/about-me/` or the corresponding
`content/about-me/index.md`:

- LinkedIn: `https://www.linkedin.com/in/hockenmaier/`.
- Twitter/X: not linked from About Me when this workflow was recorded. Ask Brian
  for his handle/profile URL and record it here when supplied; do not infer it
  from his GitHub or LinkedIn username.

Verify the active composer belongs to Brian's intended account/profile. Use
existing personal-profile audience defaults unless instructed otherwise; do not
switch to a company page or another account.

## Prepare each composer through computer use

Follow [the shared browser workflow](browser-workflow.md). Use available browser
or computer-use capabilities and the signed-in session for the intended account.
Inspect current controls instead of depending on fixed screen coordinates.

Reuse an existing draft/composer from this publication run before creating a new
one. Open the platform's observed compose/start-post control, enter the supplied
announcement and absolute article URL, and let its link preview load. Twitter
and X are one destination, not two separate posts.

The Hockenworks link card supplies the same featured image used on the site.
A separate attachment is unnecessary when the card is correct. Compare the
card's image/title/destination with the verified live article. Do not upload a
different image, replace the card with the Hockenworks banner, or add extra media.
If the card is missing or stale, check the live metadata/image URL and refresh
or repair the preview using the platform's available UI. Report a remaining
platform limitation instead of claiming that an unseen card was verified.

## Handoff and partial failures

Check that the composer contains Brian's exact text and correct article link,
with no duplicate text, extra hashtags, or unintended audience/account changes.
Capture the finished composer using the available visual-verification tools.

Leave the final Post/Publish action for Brian. Preserve each filled composer tab
using the selected browser's supported handoff/deliverable mechanism. Save as a
draft if the platform offers a reliable non-submitting option; otherwise keep
the filled composer open and identify it as unsaved. Do not navigate away merely
to obtain a shareable URL if that would discard the prepared post.

Return direct draft/composer links when available, plus retained tabs for
composers without stable draft URLs. Record completion state so retries reuse
existing work. If one platform needs login/account confirmation or cannot show
the link card, finish independent preparation on the other and report the exact
remaining step. Never submit either post as part of this workflow.
